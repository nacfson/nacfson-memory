# mem1 (`nacfson-memory` v1): Curated Cross-Agent Memory Backend

* **Author:** nacfson
* **Date:** 2026-11-23

## Overview

`mem1` (developed in the `nacfson-memory` repository and Go module) is a single-binary Go and PostgreSQL 17 backend that refines raw session context from heterogeneous AI agents—such as local coding CLIs (Claude Code, Cursor, Codex CLI) and web assistants (ChatGPT, Claude Web, Grok)—into clear, structured long-term memory across at least 100 concurrent agent requests without blocking foreground work.

Agents connect over MCP (`modelcontextprotocol/go-sdk v1.7.0+`) as the primary Day-1 wire surface. Foreground agent writes never block and never receive synchronous write-lock conflicts: every write appends straight into a non-blocking PostgreSQL inbox and returns immediately, while reads operate fail-open against curated memory. A single serialized background curation worker per workspace (starting in v1 with a single pluggable structured-output `Curator` interface plus provisional deterministic fallback) handles context-to-memory refinement, concurrency ordering, per-memory revision updates (`v1 -> v2 -> v3`), conflict resolution, and explicit retirement of outdated temporary memories (with no TTL expiration timers).

Rather than coupled whole-corpus snapshots, memories are versioned independently inside a compacted active `memory_manifest`. History retention depth (`history_retention_n`, configurable default `N` or unbounded) is tracked separately from read-time context injection (`max_tokens <= 2,000`, enforced everywhere in both runtime and benchmarks).

Development follows a strict two-layer order:
1. **Priority 1 (Context-to-Memory Refinement & Storage Organization):** Prove how raw session context is distilled, structured into priority layers (`constitution`, `durable`, `working`), updated cleanly across revisions, and retrieved accurately within `<= 2,000` tokens.
2. **Priority 2 (100+ Concurrent Request Serving):** Harden non-blocking inbox throughput, fail-open reads, connection-pool isolation, and open-loop load performance on top of the validated curation core.

This brief supersedes the 10-service Topology B blueprint in [mem1-architecture-and-research-report.html](./mem1-architecture-and-research-report.html) (Valkey RYOW, NATS, Qdrant, Temporal, S3 Git snapshots, 4 surfaces), which serves as historical research input alongside [evaluation.md](./evaluation.md).

## Analysis

### 1. Core Architectural Risks & Resolutions

1. **Context-to-Memory Refinement Pipeline & Single `Curator` for v1** (`egm-zoom-out`, `egm-design`, `egm-codebase-details`, `egm-comprehension`)
   - **Why v1 uses one `Curator` interface:** Zero-output-token decision models (`gemini-decision-1` `v1beta` preview, `TypeSafe Jev` with no official Go SDK) only score closed-set questions and cannot extract atomic claims from unstructured transcripts. Starting Phase 1 with a single pluggable structured-output `Curator` interface keeps raw-context distillation, classification, contradiction handling, and prose synthesis in one auditable background pass (while preserving the author's intent to re-introduce a Stage-1 decision pre-filter later under **Deferred / Deprecated Decisions**).
   - **Provisional fallback & self-healing:** When the external `Curator` provider times out or rate-limits, deterministic fallback writes entries strictly as `curation_state = 'provisional_heuristic'` inside `working` state (never promoting to `constitution` and never superseding `curator_verified` records). A sparse partial index (`WHERE curation_state = 'provisional_heuristic'`) replays them idempotently once the provider recovers.
   - **3 durability layers, `workspace:general` boundary & constitution protection:** Split durability into `constitution` (permanent rules such as `"I am a software engineer"`), `durable` (project decisions active until superseded), and `working` (short-lived task/prototype state retired by `Curator`), orthogonal to unified workspace scoping (`workspace:general`, per-project `workspace:<id>`, and `agent_private`). `workspace:general` holds strictly user profile, preferences, and background (language, location, career, background) and never technical decisions; technical decisions belong strictly in `workspace:<id>`. Project workspaces default to `inherit_general = 'constitution_only'` (with `workspace:<id>` overriding conflicts and per-workspace opt-out to `'none'` for strict isolation). Only `user_explicit` (or explicitly pinned/approved) writes may enter or modify `constitution`; automated background curation cannot self-promote guesses into `constitution` or promote technical decisions into `workspace:general`.

2. **Non-Blocking Inbox + Background-Only Concurrency (Zero `SEQUENCE` Gaps)** (`egm-design`, `egm-codebase-details`, `egm-implementation-readiness`, `egm-inventive-catalyst`)
   - **Zero foreground write locks:** Agents only perform lock-free append-only `INSERT`s into the raw inbox and never mutate `memory_manifest` synchronously, so 100+ concurrent agents never hit `409 Conflict` retry storms or bare PostgreSQL `SEQUENCE` visibility-gap skips. One serialized background River worker per workspace processes inbox batches in order, increments per-memory versions (`1, 2, 3...`), updates compacted `memory_manifest` (`INSERT ... ON CONFLICT`), and advances commit-safe per-layer revision watermarks.
   - **Accepted visibility lag & burst coalescing:** During the short background processing window (seconds), reading agents see the prior curated revision. Under heavy bursts from 100 agents, the worker coalesces inbox entries per topic so LLM curation latency does not create unbounded backlog growth. (Active per-agent conflict alerting is deferred to future scope so v1 stays focused on curation clarity.)
   - **Append-only rollbacks & dual mutation rule:** Cherry-pick rollbacks append a new monotonic revision (`v5` with `restored_from_version = 2`) so client version checks never move backward. Separate non-contradictory refinements (new revision on existing `memory_id`) from semantic replacements (`SUPERSEDES` pointing to a new `memory_id` that deactivates the prior entry in `memory_manifest`).

3. **No-TTL Lifecycle Management & `history_retention_n` vs. `max_tokens <= 2,000`** (`egm-design`, `egm-comprehension`, `egm-zoom-out`, `egm-structural`)
   - **Explicit retirement replaces TTL timers:** Dropping time-based TTL expiration eliminates clock-vs.-`ETag` drift and avoids deleting still-useful notes on arbitrary timers. Outdated temporary memories (such as `"use SQLite for prototype"`) are retired explicitly by the background `Curator` via `SUPERSEDE` or archival tombstones (alongside explicit user/agent delete).
   - **Two separate budget knobs:** `history_retention_n` (optional configurable default `N` or unbounded) limits how many historical revision *bodies* are retained per `memory_id` while tiny revision metadata rows stay permanently for audit; direct edits to a known `memory_id` inspect only `current` and `prev`, whereas checking contradictions against *other* memories still runs active-manifest candidate recall. Separately, read-time prompt injection enforces **`max_tokens <= 2,000` everywhere** (both runtime and benchmarks) to prevent attention dilution, KV-cache prefill spikes, and incomparable evaluation scores.

4. **Go + PostgreSQL 17 Realities, Safe Fail-Open & 3 AM Observability** (`egm-codebase-details`, `egm-implementation-readiness`, `egm-design`)
   - **PG17 & Go constraints:** PostgreSQL 17 lacks native `uuidv7()` (added in PG18) -> generate UUIDv7 in Go via `github.com/google/uuid`. Use `riverqueue/river` (`riverpgxv5`) for atomic `InsertTx` durable background jobs. Isolate foreground serving `pgxpool` (`24–32` conns, `<= 100 ms` read timeout) from background curation `pgxpool` (`4–8` conns); never hold DB connections across external provider HTTP calls. Index `pgvector` `halfvec` HNSW strictly on active manifest rows (`WHERE status = 'active'`), enable `SET LOCAL hnsw.iterative_scan = relaxed_order`, register `pgxvec.RegisterTypes` in `AfterConnect` after extension migrations, and tag vectors with `embedding_space_id`. Buffer read-path `last_accessed_at` touches in Go RAM (flush every 30–60s) and `zstd`-compress/partition `raw_sessions` monthly.
   - **Fail-open safety & security:** Never return `200 OK` with `[]` on a Postgres outage (would wipe syncing client caches). Passive context-injection reads degrade with explicit `X-Memory-Degraded` + `Cache-Control: no-store`; explicit CRUD/sync calls return `503`. Run inline deterministic secret scrubbing before persistence or any external API call, block training-enabled Free-Tier endpoints, use volume/disk TDE for searchable Postgres columns, and maintain a `purged_records` suppression table for `hard_purge`.
   - **3 AM debuggability:** Propagate W3C `traceparent` via OTel Span Links across inbox ingestion -> River jobs -> `Curator` -> manifest updates; persist a `curation_decisions` audit log; provide an `explain` lineage command, per-memory cherry-pick revert, poison-pill dead-letter queue, and runtime `curation_paused` / fallback / hourly budget kill-switches.

### 2. Core Contradictions & Inventive (TRIZ) Resolutions

| Contradiction | Suggested TRIZ Patterns | Concrete Mechanism | Secondary Operational Trade-Offs |
| :--- | :--- | :--- | :--- |
| **1. Non-blocking 100-agent writes vs. consistent per-memory revisions & curation clarity** | *Separation in Time* + *Preliminary Action* | Agents append lock-free to the inbox and never wait. One serialized per-workspace River worker batches inbox items, distills/revises memories sequentially, and updates compacted `memory_manifest`. | Bounded visibility lag (seconds) between write and curated read; requires per-topic coalescing under sustained bursts so inbox lag stays bounded. |
| **2. Independent per-memory versioning/rollback vs. `DEPENDS_ON` coherence** | *Extraction* + *Blessing in Disguise* + *Self-Service* | Pin `DEPENDS_ON` rows to `(from_rev, expected_to_rev)`. Reads emit `premise_drifted: true` with zero locks; target mutations enqueue reverse-edge dependents (`WHERE to_memory_id = $id`) for async re-verification. | Requires reverse index `(to_memory_id, edge_type)`; strict link-extraction guardrails and bounded async fan-out throttling on hub edits; clients see transient `premise_drifted` flags until re-check finishes. |
| **3. Fail-open deterministic fallback availability vs. permanent curation corruption** | *Beforehand Cushioning* + *Self-Service* | Tag fallback writes `curation_state = 'provisional_heuristic'` inside `working` state (never promoting to `constitution` or superseding `curator_verified` entries). Sparse partial index (`WHERE curation_state = 'provisional_heuristic'`) replays them idempotently when the `Curator` provider recovers. | Temporary precision dip during LLM provider outages; requires circuit-breaker hysteresis and rate-limited replay draining on recovery. |
| **4. Complete `constitution` + prerequisite context vs. hard `<= 2,000` token cap** | *Segmentation* + *Inversion* + *Self-Service* | Store both a 1-line `summary_stub` and full body per manifest entry. Fill the `<= 2,000` token cap with `constitution` + ranked full bodies first; invert overflow items/dependencies into 1-line stubs for on-demand pull rather than silent drops. | Stubs must remain faithful to full bodies; occasional extra read hop when an agent expands a stub. |
| **5. Single-node PG17 foreground throughput vs. background curation + vector recall** | *Segmentation* + *Dynamics* | Split foreground vs. curation `pgxpool` pools; restrict `pgvector` HNSW strictly to active `memory_manifest` rows; coalesce hot-topic inbox bursts with adaptive debounce windows. | Partitioned pools can leave idle foreground slots unused during heavy curation backlogs; variable time-to-consolidation under burst load. |

**Ideal Final Result (IFR):** A single-node Go + PostgreSQL 17 memory engine where 100+ agents never block on writes, a serialized background `Curator` refines noisy session context into accurate, non-contradictory per-memory revisions without TTL timers, provisional fallback self-heals after provider outages, and every read stays strictly within `<= 2,000` tokens.

### 3. Single-Node PG17 Baseline Sizing Ceilings

| Dimension | Baseline v1 Ceiling | Rationale |
| :--- | :--- | :--- |
| Concurrent requests | `>= 100` in-flight; `<= 250–500` RPS | Handled on one Go binary + PG17 node via lock-free inbox appends and bounded pools |
| `pgxpool` split | Serving: `24–32` conns (`<= 100 ms` read timeout); Curation: `4–8` conns | Prevents background curation and HNSW scans from starving foreground reads |
| Read token cap | `<= 2,000` tokens everywhere (`constitution` `<= 500` tok; overflow via 1-line stubs) | Prevents attention dilution, KV-cache latency spikes, and benchmark cheating |
| History retention | Configurable `history_retention_n` on revision bodies (metadata rows kept forever) | Bounds storage while preserving full audit lineage and safe rebase depth |
| Active vector index | Partial HNSW (`WHERE status = 'active'`), `halfvec` | Keeps active vector index RAM-resident without append-only bloat |

### 4. Deep-Dive Reference: Industry Scoping & PG17 Lexical Search

* **Industry memory scoping research (Visibility Scope vs. Durability Layer):**
  * **Mem0:** Hierarchical tuple (`app_id`/`tenant_id` -> `user_id` -> `agent_id` -> `run_id`/`session_id`), isolating private (`user_id`+`session_id`) from shared (`workspace_id`/`app_id`).
  * **Zep / Graphiti:** `user_id` core temporal graph + `thread_id`/`session_id` streams (deleting a session retains user-level facts).
  * **Letta (MemGPT):** `agent_id` core blocks + `user_id` archival search + `workspace_id` shared repositories.
  * **Supermemory:** URI `namespace` (`/ns/{namespace}`) + JSON metadata filters.
  * **Claude (Anthropic):** Hard wall between Global Memory (nightly wiki) and Claude Projects—global memory does not flow into Projects and Projects cannot see each other (prevents cross-client bleed).
  * **ChatGPT (OpenAI):** Global Memory flows across chats by default unless a Project explicitly enables project-only isolation (favors continuity, risks bleed if misconfigured).
  * **Perplexity Spaces:** Scopes retrieval strictly to the Space's document/thread container.
  * **Earlier repo research ([mem1-architecture-and-research-report.html](./mem1-architecture-and-research-report.html#L1133-L1141)):** Hard `tenant_id` partition key decoupled from soft visibility scopes (`private:user`, `agent:only`, `workspace:shared`, `team:shared`).
* **PostgreSQL 17 lexical search hosting reality:** Native `tsvector` + GIN (`pg_trgm`) is permissively licensed and runs on AWS RDS, Google Cloud SQL, Neon, and stock PG17 Docker images, but `ts_rank` lacks BM25 length normalization. ParadeDB `pg_search` (Tantivy BM25 + fuzzy matching) is **AGPL-3.0**, **unsupported on AWS RDS and Google Cloud SQL**, **deprecated/retired on Neon**, and frequently requires `REINDEX` across minor extension updates (viable only on self-hosted EC2/K8s/Docker or ParadeDB Cloud).

## Goals vs. Non-Goals

* **In-Scope Goals:**
  * Single Go binary + single PostgreSQL 17 storage and curation backend for cross-agent memory.
  * MCP (`modelcontextprotocol/go-sdk v1.7.0+`) as the primary Day-1 agent interface, mirroring revision/ETag/idempotency fields in JSON bodies as well as headers.
  * Localhost-first HTTP JSON Observability & Manual Curation API (plus CLI wrappers) inside the single `mem1` Go binary to inspect workspaces, query all memories across workspaces at once (`GET /v1/memories` via keyset cursor pagination or streaming NDJSON export, strictly separate from the `<= 2,000` token agent MCP read cap), inspect active manifest entries, revision history, dependency graph nodes/edges (`premise_drifted` flags), inbox/worker queue health, and `curation_decisions` audit trails, and execute `user_explicit` manual edits, promotions into `constitution`, cherry-pick rollbacks, `hard_purge` deletes, and kill-switches.
  * Non-blocking append-only inbox ingestion (durable `river` queue) + serialized per-workspace background curation (`Curator` + provisional fallback) focused on accurately refining raw session context into structured memories, updating revisions, and explicitly retiring outdated temporary notes.
  * Compacted active `memory_manifest` with independent per-memory versioning, append-only cherry-pick rollback, separate `history_retention_n` body pruning, and a hard `<= 2,000` token read cap everywhere.
  * Revision-pinned `memory_edges` (`DEPENDS_ON` with `(from_rev, expected_to_rev)`, `SUPERSEDES`, `WIKILINK`, `CONTRADICTS`) behind Go `DependencyIndex`, emitting lock-free `premise_drifted: true` flags on reads, bounded async reverse-edge re-verification, and 1-line `summary_stub` overflow within `<= 2,000` tokens.
  * Unified workspace scoping (`workspace:general` for user profile, preferences, language, location, career, and background—never technical decisions—plus per-project `workspace:<id>` spaces with per-workspace `inherit_general` defaulting to `constitution_only` and opt-out to `none`, alongside `agent_private`), orthogonal to 3 durability layers (`constitution` / `durable` / `working`) with `user_explicit`-only promotion into `constitution`.
  * Inline deterministic secret scrubbing before PostgreSQL persistence or external API egress.
  * Measurable Phase-1 curation quality validation (`LongMemEval_S` + `MemoryAgentBench` Conflict Resolution slice under `<= 2,000` tokens) and Phase-2 concurrency verification (`>= 100` concurrent requests via `go test -race` + open-loop load test).
* **Out-of-Scope Non-Goals (for v1):**
  * Time-based TTL memory expiration timers (retired explicitly by background `Curator` or user/agent actions instead).
  * Targeted per-agent conflict alerting system (deferred to future scope after context-to-memory refinement quality is validated).
  * Synchronous agent-facing write locks or `409 Conflict` retry loops on foreground ingestion.
  * Distributed multi-service Topology B infrastructure (Valkey RYOW, NATS JetStream, Qdrant, Temporal, Neo4j/Memgraph, S3/GCS external blob stores).
  * In-memory Go dependency graph mirror (deferred behind `DependencyIndex` until measured SQL latency exceeds budget).
  * Visual Web UI / frontend process in v1 (deferred to a future UI consumer built on top of the HTTP observability & manual curation API).
  * Client-side offline SQLite cache, 4-language SDKs, gRPC surface, and streaming SSE AI Reverse Proxy.
  * Live server-push MCP notifications (`notifications/resources/updated`), coding-agent lifecycle hooks (`SessionStart`/`PreToolUse`), and Git commit-anchor invalidation (deferred to Phase 2+ adapters).
  * Per-record KMS AES-256-GCM sub-DEKs on searchable Postgres columns.

## Alternatives Weighed

1. **Python or TypeScript primary backend** — Rejected by author: infrastructure requirement restricts primary build language to Go, Rust, or C#; Go selected for single static binary deployment, native `pgx`/River/MCP ecosystem alignment, and faster iteration than Rust or C# NativeAOT.
2. **SQLite (`sqlite-vec` + `FTS5`) as primary backend** — Rejected by author: WAL single-writer lock and brute-force vector limits fail the `>= 100` concurrent agent requirement (reserved strictly as a future optional client-side offline cache).
3. **Coupled whole-corpus snapshots (re-versioning entire memory corpus on every change)** — Rejected by author: couples unrelated memories and prevents per-memory cherry-pick updates and rollbacks; replaced with per-memory independent revisions and a compacted active `memory_manifest`.
4. **TTL-based automatic memory expiration** — Rejected by author: arbitrary timers risk deleting still-valid working notes and introduce clock-vs.-`ETag` drift; outdated temporary memories are retired explicitly by the background `Curator` or user/agent actions instead.
5. **Synchronous optimistic CAS (`409 Conflict`) and write locking on foreground agent writes** — Rejected by author: agent requests must never block or fail with write-time concurrency conflicts; foreground writes go to a non-blocking inbox and all concurrency/revisions execute in the background worker.
6. **Combining all 6 staleness mechanisms in v1** (conditional `ETag`/revision stamps, MCP push subscriptions, TTLs, lifecycle hooks, Git anchors, piggybacked stamps) — Rejected by author: overlapping invalidation paths and dropped MCP push frames add complexity before bottlenecks are measured; narrowed to lightweight revision/ETag checks in v1.
7. **In-memory Go dependency graph mirror on Day 1** — Rejected by author: premature cache-coherency complexity when indexed PostgreSQL edges handle 1–2 hop lookups in ~1–10 ms; deferred behind the `DependencyIndex` interface.
8. **Synchronous LLM curation and synchronous cosine (`>= 0.92`) deduplication on the write path** — Rejected by author: agents must never block on writes and sync cosine dedup silently merges contradictory numeric/config updates ([evaluation.md](./evaluation.md#L25-L29)).
9. **Strict globally serialized write ordering across unrelated memories** — Rejected by author: creates write-serialization bottlenecks under concurrent agents; replaced with lock-free append-only inbox ingestion and per-workspace background curation.
10. **Two-stage zero-output-token `DecisionProvider` (`gemini-decision-1` / `TypeSafe Jev`) + `ConsolidatorProvider` in v1** — Deferred by author (see Deferred / Deprecated Decisions below): v1 starts with a single structured-output generative `Curator` interface plus provisional deterministic fallback.
11. **10,000-token read cap** — Rejected by author: kept strict `<= 2,000` token cap everywhere (runtime and benchmarks) to prevent attention dilution, KV-cache prefill latency, and non-comparable benchmark results.
12. **Per-agent conflict alerting system in v1** — Deferred by author (see Deferred / Deprecated Decisions below): defer alerting until core context-to-memory refinement quality is validated.
13. **Separate `user_global` primitive or storing technical decisions in global memory** — Rejected by author: unified into a reserved `workspace:general` space (holding only user profile, preferences, language, location, career, and background—never technical decisions) plus per-project `workspace:<id>` spaces with a per-workspace `inherit_general` setting (default `constitution_only`, opt-out `none`).
14. **Flat `supersedes_id` + `memory_citations` without `DEPENDS_ON` graph in Phase 1** — Rejected by author: pursue revision-pinned `DEPENDS_ON` edges + `DependencyIndex` + 1-line stub overflow in v1 so downstream premise drift is caught immediately and connected prerequisite context surfaces together, guarded by strict link-extraction rules, hub fan-out throttling, and the `<= 2,000` token read cap.
15. **ParadeDB `pg_search` (Tantivy BM25) as Day-1 keyword search engine** — Rejected by author for v1: AGPL-3.0 copyleft constraints, lack of managed cloud hosting (unsupported on AWS RDS / Google Cloud SQL, retired on Neon), and frequent `REINDEX` requirements across minor upgrades outweigh its upside on short curated notes; v1 uses stock PostgreSQL 17 `tsvector` + GIN (`pg_trgm`) behind a swappable Go lexical search interface.
16. **Day-1 PostgreSQL Row-Level Security (RLS) for multi-organization hosting & split per-user topic copies** — Rejected by author for v1: v1 targets personal / single-deployment usage where notes on the same project topic couple into one shared topic memory (preserving contributor attribution in revisions and citations); workspace boundaries are enforced in the Go data layer while retaining `tenant_id` columns and indexes in Migration `0001` so PostgreSQL RLS remains an optional switch if external multi-organization hosting is added later.
17. **Building a bundled or standalone Web UI in v1** — Rejected by author for v1: skip frontend UI work in v1 and expose a structured HTTP JSON observability and manual-curation API inside the `mem1` Go binary so any future dashboard, script, or CLI can inspect memory architecture, dependency graphs, revision lineage, and worker health without adding a UI process.

## Deferred / Deprecated Decisions (Author Intent Preserved)

* **Zero-Output-Token Decision Models (`gemini-decision-1` / `TypeSafe Jev`) as Stage-1 Memory Classifier & Gate (Deferred from v1, Deprecated for Phase 1):**
  * **Original Author Intent:** Use dedicated System-One / zero-output-token decision models (Google `gemini-decision-1`, TypeSafe `Jev`, or future GA equivalents) as an automated memory-system governance layer to classify memories into priority tiers (`constitution` vs. `durable` vs. `working`), score keep/revise/eliminate decisions, and validate explicit dependencies with calibrated probabilities and zero output tokens.
  * **Why Deferred for v1:** `gemini-decision-1` is currently a `v1beta` preview API (no Batch API, Free Tier training caveat), `TypeSafe Jev` lacks an official Go SDK and caps at 1,200 RPM, and zero-output-token models cannot extract prose/claims from unstructured raw transcripts—requiring a generative model anyway.
  * **Re-Entry Trigger:** Re-introduce behind a batched `DecisionProvider` interface once Phase 1 `Curator` passes `LongMemEval_S` / `MemoryAgentBench` quality baselines and measured async LLM spend or throughput justifies a Stage-1 pre-filter.
* **Targeted Per-Agent Conflict Alerting System (`memory_alerts`, Deferred from v1):**
  * **Original Author Intent:** When multiple concurrent agents update overlapping swaths of shared memory, alert each involved agent specifically which shared memory changed so they refresh without blocking writes.
  * **Why Deferred for v1:** Keep Phase 1 focused strictly on refining raw context into accurate, structured memories before adding multi-agent notification workflows.
  * **Re-Entry Trigger:** Add a PostgreSQL `memory_alerts` table (piggybacked onto affected agents' next MCP response, with optional live MCP push later) in Phase 2 once context-to-memory refinement is validated and 100-agent concurrent overlap testing begins.

- **Personal / Single-Deployment Isolation (Go Layer First, RLS Switchable):** v1 targets personal or single-team deployment rather than multi-company SaaS. Workspace boundaries are enforced in the Go data layer while retaining `tenant_id` leading keys in Migration `0001`, keeping PostgreSQL Row-Level Security (`RLS`) off by default as an optional switch if external multi-organization hosting is added later.
- **Canonical Naming (`nacfson-memory` Repo/Module + `mem1` Product/CLI):** Keep `nacfson-memory` as the repository and Go module name, while standardizing on `mem1` as the product name, CLI binary (`mem1 serve`, `mem1 explain`), MCP server label (`"mem1"`), and environment-variable prefix (`MEM1_*`).
- **Build Sequence & Safety:** Layer 1 (context-to-memory refinement & storage organization + benchmark validation) first; Layer 2 (`>= 100` concurrent requests + open-loop load/chaos gates) second—with split `pgxpool` pools, durable `river` queue, `tenant_id`+`workspace_id` leading keys, inline secret scrubbing, append-only rollbacks, `hard_purge` suppression, and non-cacheable degraded passive reads vs. `503` on explicit CRUD/sync failures baked into Migration `0001`.

## Post-Review Resolution Addendum (2026-11-23)

Following the 5-stage Goldfish review in `consolidated_review_report.md`, the author resolved six scoping and architectural forks for `mem1` v1 (recorded canonically in `docs/designs/mem1-v1-design.md`):

- **Lean v1 Cut:** Drop monthly `raw_inbox` range partitioning, duplicate `'processing'`/`attempt_count`/`dead_letter` states alongside `riverqueue/river`, separate `memory_embeddings` table (inline `halfvec(1536)` onto `memory_manifest`), `purged_records` external tombstones (single-PG atomic physical delete/redaction), `agent_private`/`visibility_scope`/`actor_id`, unread `last_accessed_at` + `AccessTouchFlusher`, `runtime_controls`, OTel/`traceparent` DB columns (use `log/slog` + relational lineage), redundant `/v1/workspaces/{id}/memories`, `preview-context`, `graph` routes, and the NDJSON streaming semaphore; keep Go interfaces solely for `Curator` and `Embedder`.
- **Single-Tenant v1 / Hosted SaaS Split to v2:** Remove `tenant_id` keys/plumbing from v1 and specify multi-tenant SaaS (PostgreSQL RLS, per-tenant scoped auth, per-tenant quotas) in a dedicated follow-up v2 design after Priority 1 quality passes.
- **`'general'` Inheritance Policy (3 Modes):** Standardize workspace IDs (`'general'`, `'payments'`, etc.) and support `inherit_general IN ('constitution_and_durable', 'constitution_only', 'none')`, defaulting new project workspaces to `'constitution_and_durable'` so agent-observed personal profile facts flow automatically without manual promotion gates.
- **Query `Embedder` Latency vs. `<= 100 ms` DB SLA:** Keep `<= 100 ms` strictly as the PostgreSQL + Go recall budget (1 pipelined `servingPool` connection per `memory_recall`), give remote query `Embedder` calls a separate configurable timeout (`MEM1_EMBED_TIMEOUT`, default `2s`) with lexical fallback on error/timeout, and decouple background `Embedder` retries into `EmbedMemoryJob` so `Embedder` outages never fail curation.
- **Unified `:8787` Listener, `mem1 mcp-stdio` & Privileged MCP `memory_manage`:** Mount `/mcp` and `/v1/*` on one `:8787` listener with shared admission/payload/`Origin`/`Host`/Bearer checks, run `mem1 mcp-stdio` without port or River worker collisions, lock `memory_write` to `agent_observed`, and gate privileged `user_explicit` MCP `memory_manage` actions (`constitution`, `revert`, `purge`) behind Bearer auth plus a single-use 5-minute `confirmation_token`.
- **`DEPENDS_ON`-Only Drift & Read-Time Surface Only:** Remove `WIKILINK`, `CONTRADICTS`, and duplicate `SUPERSEDES` edges from `memory_edges`, trigger `premise_drifted: true` strictly on `supersede`, `retire`, or `revert` (attaching active replacement stubs), and defer async `ReverifyDependentsJob` cascades out of v1.
